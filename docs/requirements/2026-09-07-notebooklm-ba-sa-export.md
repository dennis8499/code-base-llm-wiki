**需求分析：NotebookLM 單一 Notebook 的 BA／SA 知識匯出**

- 文件狀態：Draft—Not ready
- 日期：2026-09-07
- 文件範圍：從當下 Codebase 全量整理業務與系統知識，產生本機 NotebookLM 文件包。
- 需求來源：本次使用者決策、現有匯出契約與 Google 官方文件。
- 確認者：需求提出者，於 2026-09-07 確認完整版本及保存路徑；同意以 Draft 狀態保存。

**1. 執行摘要**

現有匯出器固定使用 `ba_only`，SA 不會進入來源包，無法滿足使用者同時查詢 BA 與 SA 知識的需求。依據為 `.agents/skills/codebase-wiki/scripts/notebooklm_exporter.py:208` 與 `.agents/skills/codebase-wiki/references/notebooklm-export-workflow.md`。

本次修改將匯出流程擴充為：全量盤點、缺口預覽、一次確認、全面文件化與本機交付。

BG-001：每個識別出的業務功能，都具有可追溯至當下專案來源的 BA／SA 文件，並可共同放入單一 Notebook 供跨功能搜尋與問答。

**2. 利害關係人與角色**

| 角色 | 責任與權限 |
|---|---|
| 知識維護者 | 發起盤點、確認處理範圍、取得文件包 |
| BA／SA 知識使用者 | 在 NotebookLM 查詢業務流程、規則及系統行為 |
| NotebookLM 管理員 | 驗證雲端存取、資料位置及內容防護設定；匯出器不代替管理員宣告控制已生效 |

**3. 範圍與優先順序**

本次必要範圍為安全來源的全量盤點、功能覆蓋分析、每功能一組 BA／SA、跨功能導覽、來源追溯、單一 Notebook 容量檢查與本機文件包。

沿用原始專案唯讀、人工註記保留、敏感資料防護及失敗保留既有有效匯出包的邊界。

本次不包含自動上傳、修改 Google Cloud 設定、執行專案程式以驗證正式環境，或產生未實作的目標需求與系統設計。全部核心需求列為 Must，不以省略功能換取容量。

**4. 使用者旅程**

J-001：

1. 使用者發起 NotebookLM 匯出。
2. 系統唯讀掃描當下安全專案範圍，以 Wiki 作為比對基線。
3. 展示業務功能清單、已整理與未整理內容、過期或衝突證據、排除項目及預計文件。
4. 使用者確認一次。
5. 系統全面重新萃取納入範圍，產生或更新 BA／SA 與導覽。
6. 自動執行完整性、來源一致性、敏感資料及容量檢查。
7. 通過後交付本機文件包與報告，不再要求第二次匯出確認。

處理失敗時報告原因與受影響項目，保留上一份有效匯出包。若來源變動使已確認範圍失效，停止本次交付，重新盤點；不得混用不同版本內容宣稱完成。

**5. 需求**

| ID | 必要行為 | 依據 |
|---|---|---|
| FR-001 | 每次匯出必須重新盤點全部安全範圍，不得只處理既有 Wiki 或過期頁面。 | 使用者原始需求 |
| FR-002 | 預覽必須列出功能、文件覆蓋、待萃取項目、來源差異、排除與無法讀取項目。 | 使用者原始需求 |
| FR-003 | 確認預覽後必須自動處理至本機交付，移除正常流程的第二次確認。 | 使用者確認 |
| FR-004 | 每個可獨立理解與驗收的業務功能，必須各有一份 BA 與 SA，並互相連結。 | 使用者確認 |
| FR-005 | BA 必須描述有來源支持的功能目的、角色、觸發、流程、規則、結果及例外。 | BA 文件用途 |
| FR-006 | SA 必須描述有來源支持的系統邊界、輸入輸出、資料與狀態、介面及錯誤處理。 | SA 文件用途 |
| BR-001 | 業務與系統內容只能來自當下專案的程式、設定、資料結構、測試、README、規格及註解。 | 使用者確認 |
| BR-002 | 來源衝突時必須以程式碼為準，並記錄與其他來源的差異。 | 使用者明示 |
| BR-003 | 無法查證的內容必須標記「Codebase 未提供證據」，不得補寫意圖、政策、品質目標或未實作需求。 | 使用者明示 |
| FR-007 | 文件敘述必須提供可定位的來源；程式碼閱讀所得結論不得宣稱已經執行驗證。 | 可追溯性要求 |
| FR-008 | 必須提供全專案功能索引、共用詞彙及有證據支持的跨功能流程，支援 BA／SA 雙向查詢。 | 使用者確認 |
| FR-009 | 必須區分「專案未提供證據」與「尚未完成分析」；後者不得被當成知識缺口而跳過。 | 使用者確認 |
| NFR-001 | 文件必須使用繁體中文，保留識別碼、API 名稱及必要英文專有名詞。 | 使用者確認 |
| NFR-002 | 處理不得修改原始專案內容，並必須保留人工註記。 | 既有框架契約 |
| NFR-003 | 失敗不得以不完整的新包取代上一份有效匯出包。 | 既有匯出契約 |
| TR-001 | 舊 BA-only 包轉換時，必須提供同一 Notebook 內的來源替換指引，避免新舊來源混用。 | 既有靜態來源與移轉契約 |

BA／SA 是現況分析文件。文件中的驗收描述只能整理可觀察行為或既有測試依據，不能自行新增未被 Codebase 支持的需求。

**6. 驗收情境**

| ID | Given／When／Then |
|---|---|
| AC-001 | 已有完整 Wiki，但專案新增功能；重新盤點後，新功能必須出現在預覽及文件計畫中。 |
| AC-002 | 預覽已展示；使用者確認一次後，正常流程必須自動完成文件與本機匯出，不出現第二次確認。 |
| AC-003 | 專案具有多個業務功能；處理完成後，每個功能均有 BA／SA 配對、雙向連結及有效來源定位。 |
| AC-004 | README 或測試描述與程式碼不一致；文件必須採程式碼現況並列出差異。 |
| AC-005 | 專案未提供業務目的或品質指標；文件必須標示無證據，不生成推測值，也不要求業務補充才能交付。 |
| AC-006 | 有納入檔案尚未分析或功能缺少 BA／SA；檢查必須失敗並列出缺漏，不能宣稱完成。 |
| AC-007 | 文件包超出單一 Notebook 容量；整理後仍超限時必須停止，不省略功能、不改成多個 Notebook。 |
| AC-008 | 出現敏感資料殘留、處理失敗或來源版本不一致；不得發布新的有效包，上一份有效包保持可用。 |
| AC-009 | 本機檢查完成但沒有雲端驗證證據；報告必須區分本機結果與雲端未驗證狀態。 |
| AC-010 | 使用既有 BA-only 包升級；交付內容必須包含 SA，以及同一 Notebook 的來源替換指引。 |
| AC-011 | 來源含人工註記及程式識別碼；完成後原始來源與人工註記保持完整，文件敘述為繁體中文。 |

**7. 成功指標**

每次匯出以該次安全來源清單及功能清單量測：

| 指標 | 目標 |
|---|---|
| 納入來源處置覆蓋率 | 100%，每項均有分析結果或明確分類 |
| 已識別功能 BA／SA 配對率 | 100% |
| 文件來源定位與內部連結有效率 | 100% |
| 被靜默省略的業務功能 | 0 |
| 正常旅程中的使用者確認次數 | 1 |
| 未經驗證卻宣稱通過的雲端控制 | 0 |

這些指標衡量文件交付完整性；NotebookLM 實際回答品質需在租戶環境另行驗證，不以本機測試宣稱通過。

**9. Google 產品限制與安全控制**

查核日期：2026-09-07。治理採 Google 官方基準，不增加公司自訂政策。

| ID | 匯出需求與驗證責任 |
|---|---|
| CR-001 | 必須以單一 Notebook 容量檢查最終上傳來源。官方目前上限為 300 個來源，每來源 500 MB 或 500,000 字；本機採保守估算，報告數量、大小及估算方式。 |
| CR-002 | 必須對最終文件執行本機敏感資料檢查；不得把本機檢查等同於 Google 雲端內容政策驗證。 |
| CR-003 | 必須列出適用的雲端存取、資料位置及安全控制確認項目；沒有管理員證據時標示未驗證，不宣稱整體合規。 |
| CR-004 | 必須說明上傳來源為靜態副本，並提供更新與替換指引。 |

容量、靜態來源、分享與資料位置依據：[Google 產品概覽](https://docs.cloud.google.com/gemini/enterprise/notebooklm-enterprise/docs/overview)，頁面更新日期 2026-08-26。

來源內容政策由 Sensitive Data Protection 處理，問答互動防護由 Model Armor 處理；大型檔案的內容掃描另有限制，因此符合來源容量不代表必然完成雲端內容掃描。[Google 敏感資料防護說明](https://docs.cloud.google.com/gemini/enterprise/notebooklm-enterprise/docs/protect-sensitive-data)，頁面更新日期 2026-08-31。

Google 控制的適用性與生效狀態由租戶管理員驗證。本次功能交付終點為本機文件包，不要求完成雲端設定才可產生本機文件。

**10. 依賴、技術規劃與開放事項**

技術規劃需決定：

- TP-001：BA／SA 文件命名、穩定 ID、輸出結構及新版匯出契約。
- TP-002：功能文件與上傳來源的對應方式；合併或分割不得破壞每功能的 BA／SA 配對及完整內容。
- TP-003：來源版本一致性、失敗復原與確認狀態的保存方式。
- TP-004：同步修改匯出器、模板、平台入口、測試、說明文件及框架 Wiki。

目前限制：

- 全量範圍沿用現有安全 UTF-8 文字掃描能力；PDF、Word 等未支援解析的專案文件必須明列，不能宣稱已讀取。
- 既有交付紀錄曾回報 `INVALID_RECORD`，正式工作區與 Ready handoff 尚未成立。
- 品質結果：需求與驗收已整理；正式交付門檻尚未通過，本文件不可作為無條件實作基準。
